2. Registration.java

package com.example.demo;

public class Registration {
    private int id;
    private String name;
    private String email;
    private String eventName;

    public Registration() {
    }

    public Registration(int id, String name, String email, String eventName) {
        this.id = id;
        this.name = name;
        this.email = email;
        this.eventName = eventName;
    }

    public int getId() {
        return id;
    }

    public void setId(int id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getEmail() {
        return email;
    }

    public void setEmail(String email) {
        this.email = email;
    }

    public String getEventName() {
        return eventName;
    }

    public void setEventName(String eventName) {
        this.eventName = eventName;
    }
}

3. RegistrationController.java

package com.example.demo;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/registrations")
public class RegistrationController {

    private final RegistrationService registrationService;

    public RegistrationController(RegistrationService registrationService) {
        this.registrationService = registrationService;
    }

    @GetMapping
    public List<Registration> getAllRegistrations() {
        return registrationService.getAllRegistrations();
    }

    @PostMapping
    public Registration addRegistration(@RequestBody Registration registration) {
        return registrationService.addRegistration(registration);
    }
}

4. RegistrationService.java

package com.example.demo;

import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.List;

@Service
public class RegistrationService {
    private final List<Registration> registrations = new ArrayList<>();

    public List<Registration> getAllRegistrations() {
        return registrations;
    }

    public Registration addRegistration(Registration registration) {
        registrations.add(registration);
        return registration;
    }
}

WHAT THEY DO?

• git --version
	• What it does: Checks the current version of Git installed on your computer.
	• Analogy: Checking the model number of a tool you just bought.
• git config --list
	• What it does: Shows all the global settings currently configured in Git, such as your username, email, default text editor, and line ending settings.
	• Analogy: Opening a settings menu on your phone to see your personal profile and preferences.

📂 Creating and Inspecting Repositories

• git init
	• What it does: Creates a brand-new, empty Git repository (a hidden .git folder) in your current directory. If you run it again, it safely reinitializes the existing repository without losing your tracking history.
	• Analogy: Setting up a new filing cabinet inside an empty room so you can start organizing files.
• git status
	• What it does: Shows the current state of your project. It lists which files are new or modified but not yet ready to be saved (untracked/unstaged), and which files are ready to be committed.
	• Analogy: Looking at your desk to see which papers are edited but scattered, and which ones are neatly piled up waiting to be filed away.

💾 Saving Changes (Committing)

• git add .
	• What it does: Prepares all new, modified, or deleted files in the current folder to be saved in the next snapshot. The dot (.) means "everything in this folder."
	• Analogy: Putting the documents you want to save into a physical outbox before locking them in a safe.
• git commit -m "Initial commit"
	• What it does: Permanently saves your staged changes into the Git history with a descriptive message (-m) so you know what you changed.
	• Analogy: Snapping a permanent photograph of your work timeline and writing a label on the back of the photo.
• git log
	• What it does: Displays a history of all the commits (snapshots) made in the project, showing who made them, when, and their unique ID hash codes.
	• Analogy: Reading a diary or a changelog of everything that has ever happened to the project since it started.
• git diff
	• What it does: Compares your current files against the last saved version to show line-by-line differences. If nothing prints, it means you haven't changed anything since your last commit.
	• Analogy: Holding two versions of a script up to the light to see exactly which sentences you rewrote.

🌿 Managing Branches

• git branch
	• What it does: Lists all the local branches (independent lines of development) in your project. The asterisk (*) indicates which branch you are actively working on.
	• Analogy: Checking a list of alternate realities or draft versions of a book you are writing.
• git checkout feature / git switch feature
	• What it does: Both commands change your active workspace to a different branch named "feature". If the branch doesn't exist, it gives an error. (git switch is a newer, cleaner command built explicitly for switching branches).
	• Analogy: Stepping out of your main office room and walking into a side laboratory to work on an experiment.
• git merge feature
	• What it does: Combines the history and changes from another branch (like "feature") into your current active branch (like "main").
	• Analogy: Pouring the ingredients from a side mixing bowl back into the main pot.
• git branch -d feature
	• What it does: Deletes a local branch that you no longer need, usually because its changes have already been safely merged into your main project.
	• Analogy: Shredding a rough draft page after you’ve typed its final edits into your main manuscript.

🌐 Working with Cloud Repositories (GitHub)

• git clone <URL>
	• What it does: Downloads an existing Git repository from the internet (like GitHub) onto your local computer, setting up all the history and tracking links automatically.
	• Analogy: Photocopying an entire library shelf from a public institution and setting it up exactly the same way in your private study.
• git remote -v
	• What it does: Lists the web addresses (URLs) of the remote servers connected to your local project, showing where Git will send or pull data.
	• Analogy: Checking the address book labels on a package to make sure you know exactly where it is shipping out to.
• git push -u origin main
	• What it does: Uploads your local commits to the remote server (origin) on the specified branch (main). The -u flag links your local branch directly to the remote branch so you can just type git push in the future.
	• Analogy: Publishing your private local diary entries up onto your public blog website.
• git pull
	• What it does: Downloads new changes from the remote server and immediately merges them into your active local workspace.
	• Analogy: Checking a shared document online, downloading any updates your coworkers made, and adding them straight onto your desktop copy.
• git fetch
	• What it does: Downloads the latest history and new branches from the remote server, but does not touch or modify your active files. It lets you see what others have done before you decide to merge it.
	• Analogy: Looking at a notification feed to see that your friends uploaded new files, without downloading or opening those files yet.
